# DJUtil

Monorepo. Rekordbox 6/7 companion app: `agent/` (read-only master.db sync +
watch + live forwarder, CLI + tray), `server/` (FastAPI + SQLite, serves the
built PWA), `shared/` (pydantic models + sync/live protocols), `web/` (React
PWA). Windows + macOS agent; Linux server in Docker.

## Layout

- `shared/src/djutil_shared` — models (`models.py`), Camelot (`camelot.py`),
  sync protocol (`sync.py`), live protocol (`live.py`).
- `agent/src/djutil_agent` — `platform/paths.py` (OS-specific Rekordbox
  discovery), `platform/autostart.py` (Run-key / LaunchAgent),
  `rekordbox/` (reader, watcher, connection — strictly read-only,
  `PRAGMA query_only`), `sync/` (HTTP client, SyncEngine, watchdog
  debouncer), `live/` (outbox + WS/REST forwarder), `status.py`
  (thread-safe AgentStatus), `runner.py` (shared engine loop),
  `log_setup.py` (rotating file log), `tray.py` (pystray app),
  `cli.py` (typer), `gui_entry.py` (windowed PyInstaller entry).
- `server/src/djutil_server` — FastAPI app (`app.py`), auth (`auth.py`),
  sync API (`sync_api.py`), read API (`library_api.py`), live WS/REST +
  agent set-control (`live_api.py`), sets (`sets_api.py`), services
  (`services/live.py`, `services/sets.py`, `services/suggest.py`),
  backups (`backup.py`), config (`config.py`), migrations (`alembic/`),
  demo seeder (`seed.py`).
- `deploy/` — Dockerfile (multi-stage: web build + server), compose
  (`app`, `backup`, `caddy`), Caddyfile, `.env.example`.
- `agent/djutil-agent.spec` / `agent/djutil-agent-gui.spec` — PyInstaller
  console + windowed specs; icons generated by `agent/tools/make_icon.py`
  into `agent/assets/`.

## Commands

```bash
uv sync --all-packages            # install workspace
uv run ruff check .               # lint
uv run mypy shared agent server   # typecheck
uv run pytest -q                  # all tests (30s per-test timeout)
cd agent && uv run pyinstaller djutil-agent.spec --noconfirm --clean
cd agent && uv run pyinstaller djutil-agent-gui.spec --noconfirm --clean
```

## Running the agent

```bash
uv run djutil-agent check | dump --out library.json | watch
uv run djutil-agent configure --server URL --token TOKEN
uv run djutil-agent sync [--full]
uv run djutil-agent run                 # continuous sync + live forwarder
uv run djutil-agent tray                # system-tray app (same engine)
uv run djutil-agent autostart enable    # register tray at login
uv run djutil-agent autostart status
uv run djutil-agent autostart disable
python -m djutil_agent ...              # same CLI via __main__
```

Options: `--db-path`/`DJUTIL_RB_DB`, `--key`/`DJUTIL_RB_KEY`,
`DJUTIL_AGENT_DATA_DIR` overrides the agent data dir. Logs: rotating file
`<data dir>/logs/agent.log` (5 x 1 MB) for `run` and `tray`.

## Running the server

```bash
uv run python -m djutil_server hash-password   # prints argon2 hash for env
DJUTIL_DATA_DIR=./data DJUTIL_AGENT_TOKEN=... DJUTIL_ADMIN_PASSWORD_HASH=... \
DJUTIL_SESSION_SECRET=... uv run python -m djutil_server serve --port 8000
uv run python -m djutil_server openapi > web/openapi.json
uv run python -m djutil_server seed-demo --tracks 500  # refuses non-empty DB
uv run python -m djutil_server backup --dir ./backups --keep 14 [--loop-hours 24]
```

Migrations run automatically at startup. `DJUTIL_TZ` (IANA zone, validated
at startup) names auto-recorded sets. Docker: `docker compose -f
deploy/docker-compose.yml up` (with `deploy/.env`); the compose `app` and
`backup` services use `image: ${DJUTIL_IMAGE:-ghcr.io/...}` with `build:`
kept as fallback.

## Web

```bash
cd web
pnpm install
pnpm dev                 # proxies /api -> localhost:8000
pnpm lint                # eslint
pnpm typecheck           # tsc --noEmit
pnpm test                # vitest
pnpm build               # -> dist/
pnpm e2e                 # playwright (chromium only; needs dist/ + uv env)
pnpm gen:api             # regenerate openapi.json + src/api/schema.d.ts
```

## Release flow

Tag `v*` pushes run `.github/workflows/release.yml`: matrix builds both
binaries (Windows, macOS arm64, macOS x86_64) after running agent tests,
zips them (`ditto --keepParent` for the .app), uploads to a GitHub Release,
and builds+pushes the server image to `ghcr.io/<owner>/<repo>` (`:vX` and
`:latest`).
